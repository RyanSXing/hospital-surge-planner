# Backend integration

FastAPI serves identical routes under `/api` and `/api/v1` on port 8000. JSON timestamps are UTC. Send `credentials: 'include'`. Local development establishes an HttpOnly session automatically; hosted mode requires `POST /auth/login` with configured admin credentials. `GET /me` returns `{id,name,role,workspace_id,memberships,local_session}`.

`GET /workspaces/workspace-main/summary` returns `{workspace, datasets, scenarios, runs, dataset, scenario, run, inventory, context}`. Singular fields select newest available context; `dataset` is the coherent selected snapshot with history omitted and assignments filtered to snapshot time; `collection_counts`, `partial_collections`, and `full_dataset_url` declare this. Load `GET /datasets/{id}` lazily for the full data editor. `scenario` includes conditions/interventions. `run_group` aliases `run`. No forecast is invented when `run` is null. `POST /demo-datasets` accepts `{fixture:'planning_baseline'|'stress_snapshot',seed:41021,days:365}` and returns the full committed dataset.

Summary accepts optional `scenario_id` and `run_group_id` query parameters for shared URLs. A run alone resolves its owning scenario; an explicit run uses its frozen dataset even if the live draft has changed. Both IDs must identify the same scenario or return 422 `context_mismatch`; missing/unowned/wrong-kind resources return 404. Default context and list contents stay unchanged. Explicit archived scenarios and comparison runs remain readable. The selected dataset remains the bounded cached snapshot, so boot does not need follow-up full-dataset/scenario/run downloads.

`GET /datasets/{id}/units/{unit_id}/schedule` returns declared staffing rows, unit and policy. Optional `at` (defaults to the dataset snapshot), exclusive `end_at`, and exact declared `role` filter assignments whose end is after `at` and whose start is before `end_at`. Timestamps require offsets. `limit` defaults to 100 and accepts 1–500; `cursor`/`next_cursor` are stable offset pages. `total` counts every filtered assignment, while `assignments` contains only the current page. No `end_at` preserves the existing all-future-schedule behavior.

List endpoints return `{items,total,next_cursor}` and accept `limit` (maximum 200), `cursor`, and relevant filters. Scenario, dataset, run and comparison objects always have `id`. Draft mutations accept `If-Match: <revision>`; missing/stale values return 409. Create scenario with `{name,dataset_version_id,start_at,horizon_calendar_days,replications,conditions,interventions}`. `GET /scenarios/{id}` returns the scenario plus `revision` and `revisions`. PATCH returns the updated object.

`POST /run-groups` accepts `{scenario_id,replications?}` or `{scenario:<complete scenario>}` and returns HTTP 202 with `{id,status,completed,total,replications_completed,replications_requested,scenario_id,dataset_version_id,selected_replication_id}`. Poll `GET /run-groups/{id}`. States: QUEUED/RUNNING/AGGREGATING/SUCCEEDED/FAILED/CANCEL_REQUESTED/CANCELLED. Results only become final on SUCCEEDED. `GET /run-groups/{id}/metrics?grain=day|hour|week|month` returns the full ensemble contract: `scalar_metrics`, `series`, `daily`, `selected_replication_index`, `context`; `data` aliases the requested bucket rows. `GET .../heatmap` returns `{items,context}`. `GET .../replications` returns `{items,selected_replication_id}`. Replication IDs are authoritative from this response.

`GET /runs/{replication_id}/state?at=<ISO>` returns `{patients,units,vehicles,at,elapsed_minutes,context}`. `GET .../patients` returns paginated state-filtered patients. Patient detail includes events and trajectory. `/events` and `/checkpoints` are bounded paginated collections. Events accept `at` plus `direction=before|after` for exact event stepping (before is reverse chronological). Without direction, `at` requests a ±1-hour window. `POST /runs/{id}/trace` requests retained trace regeneration; poll `GET /runs/{id}/trace` until `ready=true`, then use state/events normally. Do not derive authoritative occupancy from visual animations.

`POST /comparisons` accepts `{scenario_id,plans:[{name,interventions:[...]}],replications?}` (maximum 3 alternatives). Reference is added automatically. `GET /comparisons/{id}` returns `{id,status,plans:[{id,name,run_group_id,status,metrics,improvement,feasibility,rank}],rankings,context}`. `POST .../save-plan` accepts `{plan_id,name?}` and returns a new scenario.

`POST /updates` accepts `{scenario_id,type,effective_at,state_origin:'simulation_branch'|'observed_reset',payload,replication_id?,idempotency_key?}`. `POST /updates/{id}/apply` accepts the full spec §7.8 restart payload: `{parent_scenario_revision_id,effective_at,state_origin,update_ids,source,replications,enqueue}`. Simulation source is `{parent_run_group_id,branch_strategy:"selected_replication"|"paired_ensemble",source_replication_id?}`. Selected branches inherit one actual parent history and independently sample future repetitions. Paired branches require the parent repetition count. Observed reset source is `{observed_dataset_version_id,reconciliation_policy:"replace_complete_snapshot"}`. Responses include `{update,scenario,run,run_group_id,scenario_revision_id,lineage,input_sha256,reconciliation?}`. A saved planning update can also be applied without execution using `run:false`. Correction adds a new immutable update.

Imports accept JSON bundle via `POST /imports` `{dataset:...}` or upload using `POST /imports/{id}/files` multipart `file`. Validate then commit. Drafts clone a dataset, PATCH `/entities` using `{operations:[{collection,action:'upsert'|'delete',entity?,id?}]}`, validate and commit. Exports accept `{run_group_id,format:'zip'|'json'|'csv',scenario_id?}`; status gives `download_url` on completion. Downloads require the same session. Errors use `{error:{code,message,fields},detail}`.

Canonical intervention convenience kinds: `staff_existing`, `physical_overflow`, `staffed_overflow`, `clinic`, `partner_transfer`. Full endpoint inventory is in the generated `/api/openapi.json` (also `/openapi.json`).

Admin routes: `GET/POST /workspaces/{id}/members`, `PATCH /workspaces/{id}/members/{member_id}` (If-Match), `GET/PATCH /workspaces/{id}/settings` (If-Match). Member creation accepts name, username, role, and a password of at least 16 characters. Passwords are PBKDF2-hashed; role/password changes invalidate sessions. Hosted sign-in accepts configured administrator or member credentials.

Alerts use a typed `/metric-registry`, daily/weekly/monthly evidence, selected or ensemble statistics, consecutive buckets, and revision-based deduplication. Export accepts comparison_id and optional plan_id; ZIP includes README.md, scenario.json, dataset.json, dataset-manifest.json, model-manifest.json, assumptions.csv, metrics.csv, events.jsonl, checksums.json, and comparison.csv when selected.

Placement eligibility accepts `patient_id`, `replication_id`, and `at` with the scenario context. It derives actual care/equipment requirements and tests the selected ledger, route and transport availability. Without a replication it explicitly returns `availability_source=dataset_snapshot`, never a forecast state.

Run metadata includes `source_draft_revision`, `start_at`, `end_at`, `model_version`, `input_sha256`, and optional comparison IDs. Default summary selection uses a direct scenario run and excludes plan evaluation jobs; an explicit run_group_id may open a comparison result. `GET /comparisons?scenario_id=...` retrieves saved comparison references.

Export accepts `include_events` (default true) and `replication_id` from the selected run. The chosen trace is regenerated asynchronously if required. `GET /audit-events` is admin-only and uses bounded pages of at most 200. Ordinary repetitions execute with up to `SIMULATION_WORKERS` isolated processes (default 4, hard cap 8); each completed repetition persists before aggregate publication. Cancellation polls authoritative job state and stops in-flight children cooperatively.

## Resource planning, execution estimates, and bounded replay

`POST /scenarios/{id}/feasibility` accepts a bare `ScenarioPatch` and never saves or queues it. It returns domain validation, interval-qualified exclusive reserve staffing/equipment feasibility, the current draft revision, and `compute_estimate`. The estimate uses the engine's shared local-calendar demand integration, corrected additive reports, and initial census. Run and comparison submissions reject before freeze/queue if they exceed the configured default 40 million/80 million trajectory budgets or 400,000 expected arrivals per repetition. Errors use `compute_budget_exceeded` and include the estimate plus reduction suggestions. Workspace admins can edit the two trajectory budgets.

Every job view includes `scenario_name`, frozen source revision, input hash and the persisted estimate. Comparison chart responses use a shared <=2,000-point multivariate extrema envelope across plans; each metrics context includes source indices and a detail-window endpoint template. Exact scalar outcomes and stored/exported artifacts remain unchanged. Weekly/monthly aggregations are precomputed after each run. Older run period aggregates and verified immutable traces use bounded caches.

`GET /runs/{id}/state` returns at most 500 patient records, prioritizing occupied/reserved slot patients. `patient_total`, `patient_counts` (`total`, `by_state`, `by_facility`, `by_care_level`), `patient_groups` (joint state/care/facility/unit/prior-state counts, plus target_unit_kind/admission_pending/eligible_for_transfer for exact transfer group previews), per-facility `queue_counts`, and per-facility `blocker_summary` remain exact. Queue `total` counts admission-pending patients; `ed` counts ED assessment waiting, and `ward`/`icu` identify required inpatient care. `partial_collections`, `patients_next_cursor`, and `full_paginated_patients_url` make truncation explicit. Full unit/slot/vehicle ledgers remain present. The patients endpoint accepts `facility_id`, `unit_id`, `admission_pending`, `care_level`, `state=waiting` (assessment waiting or admission pending), search, limit and cursor. Compact hourly checkpoint requests materialize this same exact bounded state.

The selected state also includes exact `transfer_paths`: `[{from_facility_id,to_facility_id,count,status_counts:{requested?,reserved?,departed?}}]`. These counts are computed from every patient before the 500-patient cap, contain no patient IDs, and describe the selected instant. Map transfer paths use this aggregate rather than inferring counts from the patient sample.

## Observability and retention

All HTTP responses include `X-Request-ID`. Structured logs contain the validated/generated correlation ID, registered route template, method, status and elapsed time; they omit raw paths, queries, bodies and credentials. `GET /workspaces/{id}/execution-metrics` is admin-only and reports process-scoped HTTP counters/latencies and workspace-scoped job statuses/timings. Worker and replication records retain elapsed/CPU/max-RSS measurements with scope labels; no sampled patient content appears in timing logs.

Workspace `retention_policy` defaults to `{unselected_trace_days:30,failed_import_days:7,export_days:7}`. Daily cleanup and the admin preview/apply operation preserve original datasets, saved scenario revisions, run inputs, aggregate results and selected representative traces. Expiration first removes live references transactionally, then deletes private objects; pending deletion metadata supports safe retry after a storage outage. `python -m surge_api.manage retention` previews; add `--apply --limit 100` to execute a bounded batch. Optional `--workspace ID` restricts scope. The admin API is `POST /workspaces/{id}/retention` with `{apply:false,limit:100}` by default.

Expired exports remain in history with `expired:true` and return HTTP 410 on download. `POST /exports/{id}/regenerate` creates a new job from the original immutable inputs. Expired unselected traces report `EXPIRED` and can be regenerated using the existing trace POST route. Failed import sessions become `EXPIRED`; users create a new import rather than reviving expired validation history. Adding a comparison report to an export preserves an explicitly selected matching run and replication; an explicit conflicting plan/run pair is rejected.

Warm annual result reads use a 64 MiB serialized JSON response cache after ownership authorization. The immutable artifact JSON cache defaults to 512 MiB of uncompressed JSON bytes (maximum 8 entries), configurable with `ARTIFACT_CACHE_JSON_BYTES`; parsed Python objects require additional memory. A separate bounded 4-state/180,000-patient reconstruction cache supports nearby replay seeks. These are process-local performance caches; PostgreSQL and checksummed objects remain authoritative. Completed comparison evidence retains only paired scalar waits and runtime feasibility for ordinary reads; older results build that compact summary once. Relative reductions summarize paired percentages only where reference waiting is positive and report the number of excluded zero-reference pairs as N/A. Ranking uses waiting, peak queue, additional staff hours, comparable explicitly supplied financial cost, earliest action readiness, then stable ID.

Dataset library cards select only metadata JSON fields in SQL and paginate before returning rows. Workspace summary selects its scenario’s dataset by ID and loads only that full source snapshot; card lists are bounded to 200 with datasets_total/datasets_next_cursor for continuation. Full immutable dataset retrieval remains explicit.

## Synthetic incident provenance

Patient `source_type` retains the canonical enum: `initial_census`, `baseline_arrival`, `surge_arrival`, or `reported_batch`. One-time synthetic incident conditions use `source_type: "surge_arrival"` and optional runtime metadata `arrival_origin: "synthetic_incident"`, `input_kind: "planned_assumption"`. This metadata is retained in patient trajectories, reconstructed state, arrival events, API patient details and exports. The explicit incident care mix is independent of the exogenous arrival-stream override. Actual reported batches retain `source_type: "reported_batch"`. Older traces containing the former `synthetic_incident` source value remain readable; new traces use the canonical enum.

### Reported arrival resource profiles

An `arrival_batch` operational payload may include `resource_profile_mix` as conditional, normalized maps:

```json
{"discharge":{"RP-ED-BASIC":1},"ward":{"RP-WARD-BASIC":0.75,"RP-WARD-OXYGEN":0.25},"icu":{"RP-ICU-MONITORED":0.6666666666666666,"RP-ICU-VENTILATED":0.3333333333333333}}
```

Each supplied care map must be nonempty, contain finite nonnegative fractions totaling one, and reference declared profiles whose stage is respectively `ed`, `ward`, or `icu`. The care group is sampled from `care_mix`; its resource profile is then sampled independently from this conditional map. Ward and ICU maps describe the inpatient stage, while the discharge map describes ED assessment. Omitting the field, or an individual care map, retains the dataset's declared selection rules. The report form resolves and saves explicit editable maps for every positive-weight care group. The original report and any correction preserve their own immutable payloads.

`facility_id` must match the selected `entry_stream_id` destination (`ED_MAIN` is the legacy default when the stream is omitted). A batch cannot silently reroute to another facility. Unknown profiles, incompatible stages, invalid fractions, and facility/stream mismatches return field-level validation errors before a report or job is created.

### Editable demand and derived summaries

Dataset drafts edit `entry_streams` and `cohorts` as the authoritative demand inputs. `arrival_profiles` (or its `baseline` alias), `hour_of_day_baseline`, and `weekday_baseline` are read-only derived collections. Stream rates sum across enabled streams; ED admission and ICU fractions use their corresponding rate-weighted disposition denominators. Hourly and weekday summaries are daily-rate-weighted averages, without changing any stream's independent profile. At zero demand, display profiles use the mean enabled-stream profile, then all declared streams; with no streams, an existing valid profile or uniform default is retained. Zero disposition denominators produce zero probabilities. Cohort-mixture arrays mirror each care group's `selection_weight` in stable dataset order; explicit per-stream pathway overrides remain independent.

Draft upserts preserve existing stream/cohort order and synchronize these summaries. Invalid intermediate edits remain reviewable with structured validation errors and cannot commit; no weights are normalized silently. Imports are never repaired: their supplied summaries must already match the authoritative inputs.
