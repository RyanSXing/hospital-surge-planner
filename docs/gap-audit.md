# Integration audit — current release status

Reviewed on 2026-10-17 against the complete P0/P1 specification. The initial implementation findings have been repaired and are retained in [the historical audit](audits/initial-integration-findings.md). They must not be read as current defects. The [acceptance ledger](acceptance-tracker.json) records the evidence and any acceptance-specific checks still outstanding. P2 remains deferred; P0/P1 scope has not been reduced.

## Open verification and release gates

- **Hosted execution:** the OCI host, network, storage buckets and instance permissions have been provisioned. Deployment of the clean release, TLS/authenticated access, a completed hosted worker job, and authenticated Object Storage export download still require the deployment smoke evidence. Local Docker or SQLite results do not prove OCI execution.
- **Final browser checks:** the full desktop/mobile matrix passed 11 tests, with 7 deliberate mobile skips for computational workflows tested on desktop. Separate recovery tests passed 2/2; candidate-resource and exact replay controls passed 2/2. Fresh desktop/mobile screenshots passed after the final contrast/layout edits (`evidence/browser-screens-final.json`) and were visually reviewed. The clone/archive lifecycle and explicit ICU-to-clinic rejection followed by a feasible transfer still need dedicated browser checks; their underlying model/API behavior is implemented and tested.
- **Long-horizon response budgets:** the 365-day, 100-replication engine benchmark passed in 409.700 seconds. This scope includes process-pool simulation, aggregation and a selected trace, and excludes API/database/artifact work. The current long-trace API cold/warm response and bounded-response evidence must be kept separate from this engine result.
- **One local queue-delay observation:** run `run_cbabe314400e4896b468` waited approximately 300 seconds after creation, then completed in 2.015 seconds. A subsequent fresh run dispatched immediately and completed in 1.795 seconds. The original delay's cause is not established; it must not be described as a confirmed logging or lease defect. Durable queue/lease recovery tests have independent passing evidence.

These are explicit verification gates, not claims that the delivered application lacks the repaired workflows below.
